# 有效，而且自己用得上

本规程只用于 P0/P1 候选，不在普通工作热路径执行。先估算实际模型调用/等待成本，复用宿主，不另建模型网关。

## 真案例与装置

优先用户提供的失败产物/明确指向的记录或获准查看的相关任务，不遍历全部私密历史。保留原请求、当时约束、最小输入、失败产物坐标、实际损失、何种结果算改善。运行前定判据，不能用提及方法名替代用户结果。

没有真实 bad case 就保留候选，效果 UNPROVEN，不编造事故；可请求一个失败例子或等待实际失败信号。若环境有 `building-mechanism-effect-cases`，读取并遵循其资格与数据纪律，双宿主基线等要求未满足必须记录，不降低标准宣称 PASS。

新上下文用相同模型、输入、工具条件，记录宿主/版本/时间及产物路径。基线与实验的实际技能列表也要取证，不能继承另一臂的对话、修改或候选文件。

| 实验臂 | 回答什么 |
|---|---|
| 无候选基线 | 真实失败现在是否仍发生？成功则是对照，不是效果案例 |
| 显式使用候选 | 方法本身能否改善？不计入自然触发 |
| 正常安装候选，原普通请求 | 没提醒能否自然发现、使用并改善？ |
| 移除关键方法步骤 | 改善是否依赖方法，而非额外提醒或更长上下文？ |
| 不同形状的相关真实任务 | 是否只记住事故措辞？ |
| 相近但不适用任务 | 是否乱加流程、变慢或产生退化？ |

自然触发臂只通过宿主正常发现 description；不显式塞正文，不点技能名，不暗示使用新方法。无法隔离就不能报触发/效果 PASS。

先选最关键真实场景跑基线与显式臂，基线全绿/显式失败就停后续昂贵实验，不为凑失败改用户请求。出现差异后覆盖主要痛点与泛化/反例，同日复跑关键基线/实验对排除偶然性。保留失败和未触发分母，不做固定通过率竞赛。

## 判断与激活

确定契约可用脚本检查，先证明已知坏产物失败、好产物通过。语义质量由主 Agent 终裁；独立上下文盲评提供建议。盲评者只看任务、材料、预定判据、乱序产物，不看哪份用了候选和预期结论。

检查器失效、零产物、基线不红、正文缺失不能算效果通过。文件打开/格式合法/模型自述不能代替实际改善。

仅以下证据成立才安装：P0/P1 因果路径；合格真实案例基线失败而实验改善；自然触发且产物改善；关键步骤消融支持实际贡献；泛化和反例无关键退化；独立评估有原始证据。删除步骤无差异则删冗余或补证据，不声称消融有效。

资源/案例/双宿主条件不足：保留候选，写具体 UNPROVEN 原因，不能拿审阅替代实验。用户后续明确改变标准，只按新限定条件报告，不改历史证据。

安装后另验用户实际宿主可见与自然消费；隔离环境成功不等于用户已用上。报告写方法改变、任务/宿主/模型、各臂触发和改善数及分母、消融、正反例、限制、实际安装与消费证据。
